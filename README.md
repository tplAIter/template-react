# React application template

A public MIT TypeScript React Router SPA with typed, cancellable CRUD data, accessible forms and navigation, five manifest generators and portable skills/exports. Next is a separate proposed modifier, never a React setting.

This source candidate renders through the existing tplaiter Go engine. Its native-v1 contract has exactly empty dependencies and contains no commands, hooks, playbooks or executable AI configuration. It does not grant Bun execution, dependency enrollment or installed CLI/MCP generation authority. Full P12 acceptance remains open.

## Dependency status

Exact public registry seeds are React/DOM19.3.0, Router8.4.0, Vite8.3.2/plugin6.1.2, TypeScript5.9.3, Vitest5.0.3 and ESLint9.39.4 with compatible pinned peers. The fixed package name is tplaiter-web-app, independent of project slug, so one genuine producer lock can match every render. bun.lock must be produced by the approved isolated Bun1.4.2 metadata-only producer and frozen unchanged; it is never handwritten or substituted from an ambient cache. Until the lock exists and separately approved artifact/runtime checks pass, installation/build/test/lint are pending, not PASS. Do not run an unfrozen install as a fallback.

## Author checks

Provide a reviewed public core checkout and external empty output directory:

```sh
CORE_DIR=/path/to/public-core REACT_RENDER_ROOT=/path/to/empty-output ./checks/native-generators.sh
CORE_DIR=/path/to/public-core ./checks/contracts.sh
```

These use the actual core APIs, never an alternative renderer. Preparation reaches TRUST_GENERATION_EXECUTION_UNAVAILABLE and performs no installed generator writes. See docs/acceptance.md for the remaining ordinary installed CLI/MCP, package and browser checks.

## Application

After explicit approved frozen package installation, run the generated project's Bun scripts. Configure only a public browser-visible VITE_API_BASE_URL, never a credential. The default /api/ prefix points to a real external backend contract; no persistence service is bundled. Backend absence is a visible typed error. See docs/architecture.md and docs/generators.md.
